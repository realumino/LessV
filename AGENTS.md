# AGENTS.md — LessV

Working rules for coding agents in this repository. Layers on top of the
operator's global agent instructions; where they overlap, the stricter rule
wins.

## What this repo is

Self-hosted Xray management plane on Cloudflare Workers (Hono + D1 + R2 +
Workflows), a React admin SPA served by the same Worker, and `lessv-node`, a
static Rust reconciler managed by systemd or OpenRC. Monorepo, single
deployable unit.

Entry docs, in order: `README.md` (operator manual: Workers, Access, nodes),
`docs/dev/architecture.md` (system design and invariants), `docs/PROTOCOL.md`
(node↔plane contract), `docs/OPERATIONS.md` (certificates/nginx/ops). Read
the one covering the area you are changing, and keep every doc true in the
same commit as the change.

## Repository layout (tracked, public)

- `src/` — Worker: Hono routers + services; `src/cert/` is the ACME subsystem
- `frontend/` — admin SPA (React + Vite), own package.json
- `node/` — Rust crate `lessv-node` (one static binary), `install.sh`,
  systemd/OpenRC units, Rust unit tests; released through Gitee Releases
- `migrations/` — append-only D1 SQL; no foreign keys by convention
- `tests/` — `pure/` (hermetic unit), `cert/` (ACME against a mock CA),
  `workerd/` (integration via the Cloudflare vitest plugin), `fixtures/`
- `docs/dev/` — contributor documentation: architecture, local development,
  testing, and releases (English)
- `scripts/` — operational tools; each carries a WHAT/WHY header docstring;
  parameters are neutral placeholders (`<token-file>`, `<node-id>`) — never
  hardcode hosts, tags, token paths, IPs, or domains
- `worker-configuration.d.ts` — generated by `npm run types`, tracked;
  regenerate when bindings change

## Local-only paths (gitignored — never commit, never print their values)

- `.plans/` — operator workspace: in-progress plans, run outputs, scratch
  notes. Plans for future work live here, not in the repo root and not in
  `docs/`. A plan may reference real hosts, tokens, or run data — that is
  exactly why it stays untracked. Never copy such content into tracked
  files or commit messages. When work completes: distill permanent
  constraints into docs/comments, distill automation into `scripts/` or
  `tests/`, then discard or archive the plan locally.
- `wrangler.jsonc` — real bindings (created from `wrangler.example.jsonc`
  by the npm pre-hooks)
- `.dev.vars`, `.env.production` — real secrets (templates `*.example` are
  committed with placeholder values only)

Generated, never edit or commit: `.wrangler/`, `dist/`, `frontend/dist/`,
`node/target/`.

## Public/local separation

The remote is public. The tracked tree carries current truth only:

- No phase or stage codenames, no execution logs, no run reports, no
  acceptance evidence.
- No real infrastructure identifiers: certificate serials or fingerprints,
  hostnames, IPs, account handles, absolute local paths.
- Conclusions worth keeping are distilled into docs or code comments;
  automation worth keeping is distilled into `scripts/` or `tests/`;
  intermediate artifacts are not stored anywhere in the tree. An important
  but non-persistable thing is resolved, not warehoused: if it matters, it
  gets a durable home (repo, VCS history, release notes); if it does not,
  the thing that generates it belongs in the repo instead.

## Documentation and comments

- Operator docs are `README.md`, `docs/PROTOCOL.md`, `docs/OPERATIONS.md`.
  Contributor docs live under `docs/dev/`. Do not add PLAN/WORKBOOK-style
  files anywhere else in the tree.
- Comments state invariants and reasons, self-contained — no references to
  plans, sessions, or files that do not exist in the tree.
- `docs/PROTOCOL.md`, `PROTOCOL_VERSION` (`src/routers/node.ts`), and the
  node version (`node/Cargo.toml`) change together in one commit; the
  protocol version is pinned by `tests/pure/protocol_freeze.test.ts`.

## Verification

Baseline before declaring any work done (all green):

```bash
npm test
npm run typecheck
npm --prefix frontend test
npm --prefix frontend run build
(cd node && cargo test)          # Linux host or a musl cross toolchain
```

- The suite is hermetic: no `.dev.vars`, no network, no real DNS. ACME in
  tests is mocked (outbound interception, see `vitest.config.ts`).
- Staging/production issuance touches real Let's Encrypt state and real
  DNS: only on explicit operator request, never in a retry loop (LE rate
  limit: 5 production certificates per week per domain).
- Deploys go through `npm run deploy` only — never bare `wrangler deploy`
  (the prebuild swaps `frontend/dist` for stubs).
- The Rust crate is Linux-only (`std::os::unix`), so `cargo test` runs on a
  Linux host; release artifacts are static musl binaries built with
  `npm run release:node` and published to Gitee Releases. Scripts stay
  cross-platform (Node stdlib, no shell assumptions) except the POSIX
  installers they ship.

## Standing invariants

- Never commit or print credentials: `ADMIN_KEY`, `KEY_SECRET`,
  `CF_DNS_API_TOKEN`, `LINODE_TOKEN`, node tokens, sub tokens, VLESS
  URIs/uuids. Tools may print certificate fingerprints to stdout during a
  run; they must not persist them into tracked files.
- `KEY_SECRET` is never rotated: it seals REALITY, certificate, and ACME
  account keys; rotation makes every sealed key unreadable.
- `/var/lib/lessv/config.json` on nodes is `lessv-node`-owned; node
  configuration changes go through the plane API, never by hand on the node.
- `lessv-node` has no runtime dependencies beyond the static binary itself
  (nginx and Xray are provisioned by `install.sh` from their vendors). Worker
  dependencies stay minimal; each addition needs a concrete justification.

## Working rules

- Investigate before planning: read the code, tests, and docs the task
  touches; verify assumptions by running targeted commands. State verified
  facts, inferences, and unknowns separately.
- Prefer the simplest implementation that is rigorous, reproducible,
  readable, and sufficient. No speculative abstractions; delete dead code.
- Deliver exactly what was requested; treat the operator as technically
  competent; no unsolicited additions or tutorial-style explanations.
- One concern per commit; imperative commit messages without phase
  prefixes.
- Do not touch operator infrastructure outside this repository (unrelated
  Linode instances, DNS records, or Workers).
